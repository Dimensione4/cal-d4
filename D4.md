# Cal.diy · personalizzazione Dimensione 4

Fork di [calcom/cal.diy](https://github.com/calcom/cal.diy) (MIT) con il brand Dimensione 4.
Branch di lavoro: `d4/main` · `main` resta uno specchio di upstream.

## Regola d'oro

Toccare il core il meno possibile. Ogni modifica a file di upstream è una **patch piccola** in `brand/patches/`, così i rebase restano semplici. I moduli nuovi (marketing, tracciamenti) vivono **fuori** dal core: servizi separati che ricevono i webhook di Cal.diy.

## Cosa è personalizzato

| Cosa | Dove | Come |
|---|---|---|
| Nome app, azienda, email supporto | `Dockerfile` | `brand/patches/01-dockerfile-branding.patch` (ARG `NEXT_PUBLIC_*` in build) |
| Home pubblica → calendario | `apps/web/app/page.tsx`, `turbo.json` | `brand/patches/02-root-redirect.patch` + `03-turbo-passthrough-env.patch`, env runtime `D4_PUBLIC_ROOT_PATH`. La 03 è indispensabile: senza la variabile in `globalEnv`, Turborepo (`yarn start`) la scarta e il redirect non scatta mai |
| Tema grafico premium (vetro, orbs, rilievo 3D, token reali di dimensione4.it) | `brand/css/d4-theme.css` → `apps/web/styles/d4-theme.css` | file nostro copiato da `apply-brand.sh`; lo importa `brand/patches/07-globals-import-d4-theme.patch` (1 riga). Regola: sul contenitore del Booker mai `backdrop-filter`/`transform` (sposterebbero gli elementi `fixed`): il vetro sta sul `::after` |
| Font Hanken Grotesk + Fraunces, logo senza inversione, titolo del login | `apps/web/app/layout.tsx`, `packages/ui/components/logo/Logo.tsx`, `apps/web/modules/auth/login-view.tsx` | `brand/patches/04`, `05`, `06` |
| Prefisso telefono predefinito +39 nel Booker (upstream usa +1 se manca l'header `x-vercel-ip-country`, che qui non esiste) | `apps/web/components/phone-input/PhoneInput.tsx` | `brand/patches/08-phone-default-it.patch` (3 righe) |
| Registrazione nascosta, link Termini e Privacy del sito | `Dockerfile`, `.github/workflows/d4-build-image.yml` | build-arg `NEXT_PUBLIC_DISABLE_SIGNUP`, `NEXT_PUBLIC_WEBSITE_TERMS_URL`, `NEXT_PUBLIC_WEBSITE_PRIVACY_POLICY_URL` (le `NEXT_PUBLIC_*` si fissano a build) |
| Loghi, favicon, icone, logo email, manifest | `apps/web/public/` | `scripts/apply-brand.sh` copia `brand/assets/` sopra i file upstream (stessi nomi) |
| Build e pubblicazione immagine | `.github/workflows/d4-build-image.yml` | push su `d4/main` → `ghcr.io/dimensione4/cal-d4:latest` |

## Aggiornare da upstream

```bash
git fetch upstream
git checkout main && git merge --ff-only upstream/main && git push origin main
git checkout d4/main && git rebase main
# se una patch va in conflitto: risolvi tenendo la logica D4, poi
./scripts/apply-brand.sh
git push --force-with-lease
```
